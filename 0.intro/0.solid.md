# SOLID PRINCIPLE
## Single responsibility principle(SPR)
- A class should have only one reason to change ,a class should have one clear responsibility ,rather than mixing unrelated responsibilities.

```
class Order:
    def calculate_total(self):
        return 1000


class OrderRepository:
    def save(self, order):
        print("Saving order to database")


class EmailService:
    def send_confirmation(self, order):
        print("Sending confirmation email")
```


## Open/Closed principle
- software entities should open for extensions,but closed for modifications.
```
class PaymentService:
    def pay(self, method, amount):
        if method == "upi":
            print(f"Paying ₹{amount} using UPI")
        elif method == "card":
            print(f"Paying ₹{amount} using Card")
```
solution:-
```
from abc import ABC, abstractmethod

class PaymentMethod(ABC):
    @abstractmethod
    def pay(self, amount):
        pass


class UPI(PaymentMethod):
    def pay(self, amount):
        print(f"Paying ₹{amount} using UPI")


class Card(PaymentMethod):
    def pay(self, amount):
        print(f"Paying ₹{amount} using Card")


class PayPal(PaymentMethod):
    def pay(self, amount):
        print(f"Paying ₹{amount} using PayPal")

```

## Liskov Substitution Principle

- Objects of the superclass can be replcabile by the objects of the child class without breaking the correctness of the program.

```
class Bird:
    def fly(self):
        print("Flying")


class Sparrow(Bird):
    def fly(self):
        print("Sparrow flying")


class Penguin(Bird):
    def fly(self):
        raise Exception("Penguins cannot fly")

def make_bird_fly(bird: Bird):
    bird.fly()


make_bird_fly(Sparrow())  # Works
make_bird_fly(Penguin())  # Fails
```

```
class Bird:
    pass


class FlyingBird(Bird):
    def fly(self):
        print("Flying")


class Sparrow(FlyingBird):
    pass


class Penguin(Bird):
    pass

def make_bird_fly(bird: FlyingBird):
    bird.fly()


make_bird_fly(Sparrow())  # Works
```
